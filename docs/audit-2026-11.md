## 4. Operation undo (new)

`src/main/git/undo.ts`, wired in `src/main/ipc.ts` via the `UNDOABLE` table in `src/main/handlers.ts`.

- **Covered:** commit, amend, branch create/checkout/rename/delete, tag create/delete, merge, rebase,
  interactive rebase, cherry-pick, revert, reset, "create branch here" from the reflog. Up to 30 steps
  per repository (per worktree) while Spoon is running.
- **How:** inside the repository lock, Spoon snapshots `HEAD` (symbolic name and commit) and every
  `refs/heads/*` and `refs/tags/*` before and after the command. Operations that stop (conflicts,
  `edit`) are not recorded — Abort is the right tool there.
- **Safety:** undo only runs when every reference the operation changed is still exactly where the
  operation left it and HEAD has not moved; otherwise it is refused (`STALE`) with the reason, so it can
  never overwrite later work. Refs are moved with compare-and-swap `git update-ref <ref> <new> <old>`.
  The checked-out branch moves with `git reset --soft` (undoing a commit keeps its changes staged),
  `--mixed`/`--soft` (undoing a reset of that kind) or `--keep` (anything else: Git refuses rather than
  overwrite local changes). Switching back to a previous branch uses plain `git checkout`, which also
  refuses to overwrite local changes. Reflog entries are tagged `spoon: undo <label>`.
- **UI:** toolbar **Undo**, command palette "Undo last Git operation…", **Ctrl/Cmd+Z** (ignored inside
  text fields). The confirmation lists every reference change, e.g. "Move main from 1fdd02d back to
  97b2359", "Switch back to main", "Delete feature/x (created at …)".
- **Not covered:** staging, discards, stashes, pushes and anything done outside Spoon; no redo; the
  history is in memory only.

### Repository Statistics (new)

Entry points: **Statistics** in the sidebar (under Reflog) and "Show repository statistics" in the
command palette. User documentation and the full counting rules are in
[workflows.md](workflows.md#repository-statistics).

Research ([research/statistics-2026-11.md](research/statistics-2026-11.md), official sources only):
Fork added Repository → Statistics in Mac 1.0.97 (21 Aug 2020) / Win 1.53 (31 Jul 2020), weekday and
hour charts in Mac 1.0.99 / Win 1.54, a time range in Mac 2.4 / Win 1.59, `.mailmap` support in Mac
2.3 / Win 1.61, and a Repository Treemap in Mac 2.52 / Win 2.8. Fork does not document its branch
scope, merge handling or line counts. GitHub Insights counts the default branch only, excludes merge
commits ("All statistics exclude merge commits", REST statistics docs) and buckets the punch card by
each commit's own time zone. Spoon follows those documented rules and states them in the UI.

| Decision        | Spoon's rule                                                                                           | Why                                                              |
| --------------- | ------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------- |
| Scope           | Current branch / detached HEAD, or all local branches; each commit once                                | Requested; GitHub/GitLab let you pick a branch                   |
| Date field      | Author date in the author's recorded time zone (`%ai`), range inclusive by calendar day                | Matches GitHub's punch card; independent of the viewer's machine |
| Merges          | In the total and listed separately; excluded from contributor commits and all line/file numbers        | GitHub excludes merges; a merge diff repeats counted work        |
| Identity        | `.mailmap` (`%aN`/`%aE`), grouped by e-mail                                                            | Git's own mapping; Fork supports `.mailmap`                      |
| Files and lines | `--numstat -M` vs first parent; rename = one change for the newest name; binary = change without lines | Deterministic, matches `git log --numstat`                       |
| Shallow         | Labelled "based on the available local history only"                                                   | Requested                                                        |

Implementation: `src/main/git/stats.ts` (read-only `rgit`, never under the write lock). The overview
is one `git log` over the scope; the file statistics feed only the in-range non-merge commit ids to
`git log --no-walk --stdin --numstat -M`, so short ranges stay fast on long histories. Both queries
carry an operation id; the view cancels the previous query whenever the repository, scope or range
changes and ignores late results, keeps the previous numbers visible (dimmed) while refreshing, and
reloads when refs change (Spoon or external Git, via the watcher). File statistics are cached by
branch tips + range + `.mailmap` content.

## 8. Windows CI failure: commit swept untracked files in (fixed)

The Windows CI log of run 7 (provided by the maintainer) showed the existing E2E test "open a
repository, stage, commit, branch and browse history" failing: after staging only `app.ts` and
committing, the untracked `notes.txt` had been committed too.

**Cause (app bug, not the test):** the commit box chose "Stage all and commit" when the renderer's
cached status showed nothing staged, and ran stage-all and commit as two separate calls. Pressing
Ctrl/Cmd+Enter right after staging a file — before the status refresh arrived — therefore staged
**every** change, including untracked files, and committed them. The fast CI runner hit that window;
the slower local machine did not.

**Fix:** `commit.create` takes `stageAllIfNothingStaged`; the main process checks the real index
inside the same locked call and stages everything only if nothing is staged. A commit the user
limited to staged changes can no longer pick up other files.

**Evidence:** a new E2E test stages a file outside Spoon and commits immediately, before the watcher
refreshes. Against the unfixed build (`d6dde34`) it failed 4 of 4 runs with `notes.txt` in the commit;
with the fix it passed 5 of 5. Two integration tests cover the rule (staged-only commit keeps
unstaged and untracked files; an empty index stages everything).
