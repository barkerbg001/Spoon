# Audit and parity report — November 2026

Date: 2026-11-07. Platform tested: **Windows 11 Pro (10.0.26300) x64, Git 2.33.0.windows.2, Node 22.14,
Electron 44.7**. Nothing was run on macOS or Linux.

This report records what was audited, what competitors do better, what changed, how it was verified,
and what is still open. Competitor sources (with URLs and versions) are in
[research/competitors-2026-11.md](research/competitors-2026-11.md); earlier research is in
[research/fork.md](research/fork.md) and [research/competitors.md](research/competitors.md).

## 4. Operation undo (new)

`src/main/git/undo.ts`, wired in `src/main/ipc.ts` via the `UNDOABLE` table in `src/main/handlers.ts`.

- **Covered:** commit, amend, branch create/checkout/rename/delete, tag create/delete, merge, rebase,
  interactive rebase, cherry-pick, revert, reset, "create branch here" from the reflog. Up to 30 steps
  per repository (per worktree) while Spoon is running.
- **How:** inside the repository lock, Spoon snapshots `HEAD` (symbolic name and commit) and every
  `refs/heads/*` and `refs/tags/*` before and after the command. Operations that stop (conflicts,
  `edit`) are not recorded — Abort is the right tool there.
- **Safety:** undo only runs when every reference the operation changed is still exactly where the
  operation left it and HEAD has not moved; otherwise it is refused (`STALE`) with the reason, so it can
  never overwrite later work. Refs are moved with compare-and-swap `git update-ref <ref> <new> <old>`.
  The checked-out branch moves with `git reset --soft` (undoing a commit keeps its changes staged),
  `--mixed`/`--soft` (undoing a reset of that kind) or `--keep` (anything else: Git refuses rather than
  overwrite local changes). Switching back to a previous branch uses plain `git checkout`, which also
  refuses to overwrite local changes. Reflog entries are tagged `spoon: undo <label>`.
- **UI:** toolbar **Undo**, command palette "Undo last Git operation…", **Ctrl/Cmd+Z** (ignored inside
  text fields). The confirmation lists every reference change, e.g. "Move main from 1fdd02d back to
  97b2359", "Switch back to main", "Delete feature/x (created at …)".
- **Not covered:** staging, discards, stashes, pushes and anything done outside Spoon; no redo; the
  history is in memory only.

## 5. Test evidence

New tests (all against disposable repositories and local bare remotes):

- `tests/integration/workflows.test.ts` (16): pinned lease survives a background fetch; null lease
  refuses an existing branch; rejected push → fetch + rebase + push with remote order checked; pull
  `--rebase` conflict returns a stopped operation and aborts back to the original commit; diverged
  ff-only pull; pickaxe search; published-commit detection; undo of commit (Unicode path with spaces,
  unrelated unstaged edit preserved), amend, merge (dirty unrelated file preserved), branch delete,
  rename of the current branch, create-and-checkout, interactive rebase (order and contents), soft
  reset; undo refused after an outside commit; stopped merge not recorded.
- `tests/integration/worktrees.test.ts` (3): dirty worktree with a space and non-ASCII name — change
  list, refusal without force, removal with force, branch kept; main/current/unknown folders refused;
  locked worktree needs force.
- `tests/e2e/workflows.spec.ts` (7, Playwright driving the built Electron app): line staging then
  commit then toolbar Undo (`git diff`/`git diff --cached` checked at each step); interactive rebase
  drop + fixup then Ctrl+Z; rejected push recovery; stale force-with-lease refused + fetch; rebase
  conflict + Abort; dirty worktree removal; two-sided compare.

Bugs found by the new tests: the Windows 8.3 short-path mismatch in worktree matching (fixed with
`realpath`), and the "HEAD is detached" message when Push is clicked before status loads (fixed).
Test-suite races found and fixed (the app was not at fault):

- The existing E2E test "discarding requires explicit confirmation" was **flaky before this work**:
  on an untouched checkout of `0d8563c` it failed 1 of 2 runs. Cause: the test's own verification
  `git status` refreshes the index and takes `index.lock` at the moment Spoon runs `git checkout` for
  the discard, so Spoon's command fails. With the test helper using `GIT_OPTIONAL_LOCKS=0` (as Spoon
  does for its own read-only calls) the same baseline passed 6/6. Both E2E files now do this.
- The new interactive-rebase E2E test first polled for a commit list that already reads
  `c1, initial` midway through the rebase; it now waits for the rebase to finish.
- One cold-start run of the rejected-push E2E test failed before the readiness wait was tightened; it
  did not reproduce in 11 later runs. E2E failures now save a screenshot to `test-results/`.

Final results: `npm run check` passed (10 files, 96 tests); `npm run test:e2e` 11/11; the 7 workflow E2E tests also passed against the packaged `dist/win-unpacked/Spoon.exe`. Details in [progress.md](progress.md#latest-results-2026-11-07-windows-11).

No performance work was done in this pass, so no benchmark was re-run.

## 6. Highest-value remaining gaps

1. Conflict prediction before merge/rebase/cherry-pick/pull (needs Git ≥ 2.38 on a test machine).
2. Operation detection via Git (`rev-parse --verify CHERRY_PICK_HEAD`) and a reftable test (Git ≥ 2.45).
3. Redo, and undo for staging/discard/stash (Tower parity).
4. Commit-list editing directly from the graph (move up/down, squash selected, edit message).
5. Push that honours `push.default`/`pushRemote` and a `--dry-run` preview.
6. macOS and Linux runs of the full suite and packaging.
7. IPC trust check and Windows 8.3 short paths: a development build run from a checkout whose path
   contained a short name (`BARKE_~1`) rejected every IPC call and showed a blank window, because
   `isTrustedUrl` compares the renderer file path as text. It should compare canonical (`realpath`)
   paths. Not fixed in this pass: it is security-sensitive and needs its own tests.
